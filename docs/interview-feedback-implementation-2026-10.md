# 두 차례 면담 피드백 반영 기록 — 모두의 딸깍 연구소

작성 기준: 2026-10-10 · 사용자가 직접 제공한 **두 차례 면담 정리문** 및 실제 GitHub 코드.  
이 문서는 면담 **원음성 전사 전체를 직접 검증했다는 뜻이 아닙니다.** 면담자의 조언과 아래의 추가 설계 판단을 구분해 기록합니다.

## 1. 두 웹사이트를 분리하는 원칙

| 구분 | 대학 학부 연구실 홈페이지 (면담의 직접 평가 대상) | 모두의 딸깍 연구소 (현재 수정한 프로젝트) |
|---|---|---|
| 주목적 | 실제 연구실 구성원과 연구실 활동·성과의 공식 포트폴리오 | 학생이 AI 사례를 직접 만들어 보고 HAI 연구방법을 학습하는 **독립** 실습·연구 플랫폼 |
| 콘텐츠 중심 | 소속·연구진·논문·발표·자격·증빙·연구 프로젝트 | 실제로 작동하는 UI 데모·학습 과정·HAI 프로토타입·검증 가능한 코드 |
| 대외 신뢰성 | 지도교수 및 기관 공식 정보 승인 필요 | 대학·기관 대표 사이트인 것처럼 표기 금지 |
| 사람·업적 | 실존하는 연구원과 서류를 확인하고 동의받은 뒤 공개 | 증빙과 명시적인 동의가 **있는 경우에만** 개인 포트폴리오 추가 |
| 자동화 | 연구실 내부 시스템 접근 통제 | 공용 샌드박스 데모와 미래 아키텍처를 구분. 실 AI 도구 실행으로 속이지 않음 |

**직접 받은 피드백**은 학교 연구실 홈페이지에 대한 평가였다. 우리는 그중 일반화할 수 있는 기본 UX·정보구조·증빙 원칙을 딸깍 연구소에 선별해 적용했다. 이 두 사이트를 하나의 공식 대학 연구실로 합치지 않는다.

## 2. 면담에서 전달받은 핵심 사용성 피드백과 반영

| 면담 기반 항목 | 현 사이트 발견 상태 | 이번 적용 |
|---|---|---|
| 과도한 여백·큰 메인 그래픽 | 홈페이지 히어로 높이 최소 740px·약 100px 상하 패딩, 섹션 상하 106px | 히어로의 강제 최소 높이 해제, 반응형 패딩 단축, CORE 크기 조정, 섹션 수직 리듬 공통화 |
| 산세리프·본문 약 1.6 행간 | 학생 페이지는 1.65, 역사적 연구 페이지는 별도 스타일 | 공통 시스템 산세리프, 학생 본문 1.62, 한글 `word-break: keep-all`과 자연스러운 줄바꿈 |
| 강한 색의 남용 | CORE/HAI에 다크·시안/오렌지, 본문에 절제된 파랑 | 기존 학생 페이지의 중립적 팔레트 유지; CORE/HAI에서만 시각적 강조, 산만한 강조 확대 방지 |
| 클릭 가능한 것처럼 보이는 미작동 버튼 | 프로젝트 카드 자체는 이미 `Link`로 전체 클릭 가능; **ProjectVisual의 검은 가짜 프롬프트 버튼**이 미리보기임을 나타내지 않음 | 정적 프롬프트를 PREVIEW로 전환, 실제 기능 없는 화살표 제거. 카드 전체 링크·키보드 포커스 유지 |
| 활성 메뉴 표시 | 이전 업데이트에서 `aria-current`와 활성 스타일 이미 구현됨 | 유지, 새로운 출력 자료는 실제 링크로 하단·아카이브에 연결 |
| 프로젝트 보드 균형과 정보 밀도 | 카드 크기·패딩 여유 많고 주로 이름·기술 소개 위주 | 시각 카드 높이 축소, 그리드 간격 조정, 각 항목에 현재 **검증 상태** 표시 |
| 프로젝트별 질문·방법·성과 증빙 | 개별 상세 페이지는 있지만 연구 질문·검증 근거 필드가 없음 | 구조화된 `researchQuestion`, `researchMethod`, `verification`, `outputEvidence`, `sourcePath`를 프로젝트 4개에 도입. 상세 페이지에 근거·소스 링크 추가 |
| 논문·수료·자격·포트폴리오 | 현재 검증된 공개 레코드 없음 | `/outputs`에 실제 공개 소스·로컬 실습·설계 문서만 링크. 논문·연구자·자격·수상 게시 기준 명시. 가상 인물이나 실적 추가 안 함 |
| 인간–AI 상호작용과 실제 연구 차이 | Research 페이지는 HAI 중심 기본 소개만 존재 | **AI를 연구 도구로 사용하는 것**과 **AI와 인간의 상호작용을 연구하는 것** 구별. 정치정보·AI 요약 사례는 미실행 연구 설계 아이디어라고 표시 |
| 모바일 반응형 | 기존 820/560px 브레이크포인트 | 920/640px 밀도 추가 점검용 CSS, CORE·그리드·증빙 카드가 세로로 쌓이도록 재배치. **실제 기기 검사 별도 필요** |
| 학부 연구생 공개 역량 | 대학 사이트의 실존 연구원 정보는 별도 | `/outputs`에 학술 성과·자격·팀 정보의 공개 요건만 마련, 제출·검증·동의 전에 명단을 노출하지 않음 |
| HAI 자동화 시연 | 기존 마이크 동의 기반 Clap HAI 및 Agent Company 설계 시각화 | 보존. MCP 실제 실행은 아직 미연결. 작동 중인 실험과 미래 목표 분리 |
| 실제 외부 링크와 출처 | GitHub 소스 링크가 연구소 저장소 루트로만 연결 | 프로젝트 상세 화면에서 실제 관련 `src/components/...` 파일로 직접 링크, 결과물 페이지에서 검증 가능한 작업 항목 연결 |

## 3. 이 프로젝트에 맞는 결과물 구분

**코드·프로토타입**은 사용자에게 작동 모습을 보여줄 수 있지만, 인간 대상 효과 검증·논문·기관 인증과는 다르다.

현 구조는 다음을 구분한다.

- `사용 가능한 데모`: 방문자가 브라우저에서 기능을 사용할 수 있음. 자동으로 AI API가 연결되는 것은 아님.
- `기획 예시`: 가상 수치와 인터페이스 목업. 실제 성과 데이터 없음.
- `연구 실험`: 동의를 받고 사용해 볼 수 있는 프로토타입. 정량적 실증 성공이나 연구 효과를 주장하지 않음.
- `공개된 자료`: 코드·도구·설계 문서에 실제 연결 가능한 소스 링크가 존재함.
- `논문/수상/인증`: **증빙 링크, 발급처, 일자, 공개 허락**이 확인된 경우에만 별도 유형으로 게시.

## 4. 향후 학부 연구실 홈페이지 전용 확장 요구 사항 (현재 딸깍 연구소에 허위 적용하지 않음)

- 연구원 프로필: 실명, 공개 동의, 역할, 프로젝트 링크, 업데이트 날짜.
- 논문·학술발표·포스터·보고서: 유형, 저자, 발행처, 연도, DOI/파일 링크, 출판 상태, 취소/정정 기록.
- AI 자격증·교육 수료·수상: 서로 다른 유형, 발급기관, 발행일, 증빙 원문, 공개 허락 및 유효 기간.
- 연구 프로젝트: 질문, 설계, 모집/윤리, 데이터 출처, 참여자·역할, 진행 상태, 결과 코드, 분석 한계.
- 공식 소속 표시: 지도교수/학과/기관의 승인 없는 대표성 표기 금지.

## 5. 다음 QA 게이트

자동화: `npm ci`, `npm run lint`, `npm run build`, `npm run smoke`.
프로덕션 요청 검사: `/outputs`·`/projects/*`·`/research` 등 경로 상태, 가상 성과 구분, 소스코드 링크.

**별도 확인 필요**: 390/768/1280px 브라우저 스크린샷에서 실제 여백·텍스트 줄바꿈·프로젝트 카드 높이 점검, 키보드/모바일 탐색, Safari/iOS 및 Android 실마이크 테스트, WCAG 색 대비 검토.

완료하지 않은 실제 연구나 논문·인증·대외 협업을 꾸며 낸 채 공개하는 것을 금지한다.
